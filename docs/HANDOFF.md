# 引き継ぎ: LSX-Dodgers の MZ-2500 移植

最終更新: 2026-11-05 / 担当AI: Claude(次の担当もClaudeを使う想定)。**AIの記憶(メモリ)は引き継がれないので、この文書とdocs/が唯一の文脈です。**

## 1. 30秒サマリ
- **目的**: CP/M互換OS「LSX-Dodgers」(tablacus氏)を MZ-2500 へ移植する。移植元は MZ-700/1500版(`M7*.ASM`)。
- **現状**: ビルドでき、**実IPL ROMで起動するエミュレータ(mz2500-web-emulator のCLI)上で** 起動 → `DIR` → `COPY`(読み書き)→ `FORMAT.COM`(**物理+論理フォーマット**)まで動作。X1/MZ-700のLSXで作った標準形式の2D/2DD(空き容量 2D=362496 / 2DD=730112)も読み書きできる。
- **未確認**: **ユーザーの手元のエミュレータ/実機での最新版の確認は取れていない。** 最後に確認が取れた最新の報告は旧版(C/D版が真っ黒)で、その原因は修正済みだが、ユーザー環境での再確認はまだ。
- 成果物: `dist/LSX2500_80col.d88`(推奨)、`LSX2500_40col.d88`、`LSX2500_40col_noiocs.d88`、`LSX2500_80col_noiocs.d88`(IOCSを一切呼ばない80桁。2026-11-05追加)(いずれも標準LSX形式の2DD起動ディスク)。

## 2. 最初にやること(5分)
```bash
# 必要: gcc g++ make perl python3 unzip tar patch (cmake不要)
tools/setup_env.sh <作業dir> <z88dk-*.tgz か z88dk の git 作業ツリー> <mz2500-web-emulator-main.zip> <ROMS.zip>   # z80asmとエミュレータCLIを作る(数分)
source <作業dir>/env.sh
tools/build_all.sh <LSX-Dodgers-master(原本の.ASMのあるdir)> <ldsys.d88> <出力dir>      # 4種類をビルド
tools/test_all.sh <出力dir>                                                           # 68本 PASS になること(約12分。ワイルドカード4・LOCK/カナ4・ブート時セクタ不良2・読み出しエラー復帰4・MON往復4・ビープ1・C:,D:/E:/F: 22を含む)
```
- ゼロから再現できることを確認済み(2026-11-04: 9/9 PASS・配布イメージとバイト一致。2026-11-05: z88dk を git clone して新しい作業dirで setup → build → test が 18/18 PASS(その後カーソル点滅・80桁IOCSなし版を足して27本)、再ビルドしたイメージとバイト一致)。
- 必要な入力ファイルは §6。ROM・マニュアル・原本ソースは**著作物なのでこのリポジトリには含めていない**。ユーザー(各自)から受け取ること。

## 5. 判断の経緯と「間違えたこと」(同じ轍を踏まないために)
1. **`not master`**: D88のデータは全バイト補数で、レコードrは `r XOR 10h` の位置(r=0はcyl0/head1/sec1)。素のデータを書いていたので `IPLPRO` が見つからなかった。
2. **ローダをバンク2/3に置いた**: IOCSは呼び出し中バンク1〜3をROMに替え、戻りで復元する。ローダはバンク4/5(8000h〜)へ。
3. **`TINIT` 前に `IM 1`**: IOCS内の割り込みが IM2 のベクタ表を使えず暴走。`TINIT` の後で `IM 1`。
4. **`CHKEY` のビット判定が逆**(キーは0=押下)/ **VRAM第3プレーンの計算ミス**(`+1800h`ではなく`+1000h`)。自作Z80エミュレータで発見。
5. **VRAMセル形式を仕様書の測定式のまま使った**: 16ライン文字では `Text1=(c&3Fh)*4`(偶数コード、R=0)、空白/消去=`80h`。`+2`(R=1)は8ライン用で、16ラインで使うと上下2回描かれる。エミュレータのソース(`renderer.cpp`)で判明。
6. **IOCSを呼ぶ間、スタックをバンク6に置いた**: IOCSはVRAMアクセスにバンク6(C000h〜)を使う。ブート標準のSP=FC00h(バンク7)のまま呼ぶ(`KEEP_ENV`)。
7. **`DDh`(ヘッド選択)の極性で往復した**: IOCS仕様書の「bit0=0でヘッド1」は**誤り**。実IPLはレコード0を `DDh=13h` で読む。ただし**標準ディスクは「偶数トラック=ヘッド0」**で `DDh` bit0=トラックの偶奇。IPLレコード規則(`r XOR 10h`)はIPL用トラック専用。
8. **データの補数**: X1/MZ-700のイメージはディスク上が素のデータで、反転バスのMZ側は**ソフトでCPL**して読み書きする(原本のMZ-700ドライバのまま)。IPL用トラックだけ補数。
9. **独自レイアウト(256B×16、システムを予約領域に隠す)を作った**: X1/MZの標準ディスクが読めず、起動ディスクの `DIR` にシステムが出なかった。→ 標準LSX形式(512B×9、BPB、FATにシステムファイル)に作り直した。ユーザーの指摘で発覚。
10. **z80asmの環境変数**: `Z80ASM` という名前の環境変数を使うと、z80asm自身がそれを読んで誤動作する(`LSX_Z80ASM` を使う)。
11. **z80asmの癖**: `PHASE` は本ソースの使い方と相性が悪い → 本体を `ORG BDOS` の別モジュールで組む。`DS 式-$` の `$` はセクション先頭からの相対 → `ORG_BASE` で補正(`ld2z80asm.py`)。この変換でMZ-700版の本体9182バイトが原本 `LDI.MZT` とバイト一致する(ハーネスの信頼性の確認)。
12. **`FORMAT.COM`**: ドライブの**現在のDPB**でフォーマットする。メディア未読(初期DPB=2D)で実行すると2D用FATを書く。原本のLSXと同じ挙動(のはず。X1/MZ側で同じ手順を再現しての確認はしていない)。
14. **時間基準が止まってハング**: `C6h`=0(全割り込み許可OFF)にすると `E1h` bit0(/VBLANK)が動かず、`RD556VSYNC` を使うタイムアウト(ディスクが無いドライブ、キーリピート)が永久に終わらない。`C6h`=08h(VBLANKのみ許可)+`0038h`を`EI; RETI`に。`test_all.sh` に回帰テストあり。
15. **物理フォーマットが効かなかった(機種IDの問題)**: `FORMAT.COM` はBDOS 6Fhの機種ID(L)が 0(X1)/1(MZ-700)/2(PC-88) のときだけ物理フォーマットに進み、他は「logical format」のみ(未フォーマットだと `Error!`)。本移植の `MAC=4` が原因。**`MAC=1` にすれば物理フォーマットは動くが、`MODE.COM` がMZ-700用の処理で画面変数を書き換えて表示が壊れる**(`mode 40` で `ld2500.bimno` のように化ける)ため不可。`MAC=4` のまま、取り込み時に `FORMAT.COM`(v1.22)の判定 `CP 1` を `CP 4` に1バイト変更(`tools/make_boot_disk.py` の `patch_format_com`、バイト列が一意に一致したときのみ。`LSX_NO_FORMAT_PATCH=1` で無効)。物理フォーマット後の構造(160/80トラック、9×512B、C/H一致)と空き容量を別コードで確認。MAG/GL3/EMM は機種ID 0 専用なので元々動かない。**実機の Write Track は未確認**(エミュレータのFDCは寛容な可能性がある)。
16. **カーソル点滅**: ハードのBL属性(bit7)は字形のドットを消すだけなので、空白セル(行末)のカーソルは `RV+BL` でも点滅しない(`renderer.cpp`)。S-OS移植版の点滅はIOCSの `CURBL`(タイマ割り込み+IOCS用RAM 2456h〜245Chのセル値)によるが、LSXはそのRAMをTPAに使い割り込みも止めているので流用不可。→ `FLGET` の待ちループでVBLANK(`RD556VSYNC`)の立ち上がりを30回数えるたびにRVを反転(`tools/make_m25_from_m7.py` と `M25IO.ASM` の両方を更新、差分はFLGETのみ)。点滅するのは1文字入力待ち(コマンド入力・`INPUT`系)の間だけ。
17. **IOCSなしの80桁**: `MZ_TRACE_ALL=1 --trace-io` で `TINIT` の A=08h(80桁)と A=09h(40桁)の全ポート書き込みを比べると、差は `E8h`(48h→68h、bit5=CH80)と CRTC レジスタ7(08h→09h)・8(58h→59h)(横表示範囲)だけ(F4h=レジスタ番号、F5h=データ)。`M25INIT.ASM` の `COLS80` かつ `USE_TINIT` なしでこれを直接書く。`--trace-io` は既定では E8h を記録しない(`MZ_TRACE_ALL=1` が必要)。TINIT の実行は約260フレーム目(それ以前に比較しても差が出ない)。**実機/他エミュレータでの80桁は未確認**。
13. **dummy IPL(ROMなし)**: ペイロードを固定位置(レコード16〜、cyl0/head0から)から読むため、標準LSXの先頭トラックと衝突する。実IPL(`--real-ipl`)では起動する。

## 7. 資料の信頼度(要注意)
- **IOCS仕様書は測定に基づく互換ROM作成中の資料で、誤りがある**: `DDh` の極性(§5-7)、VRAMセル式がフォント状態に依存することの記述不足(§5-5)。**迷ったら実IPL ROMのトレースとエミュレータのソースで裏取りする。**
- ユーザーズマニュアルの I/O 表は概ね信頼できた(`DDh`のサイド選択は `1:サイド1` で実機動作と一致)。
- `E1h` bit0 は `/VBLANK`(0=ブランク中)と英語版仕様書にあるが、独立には未検証(キーリピート/FDCのタイムアウトの時間基準にだけ使用)。

### 5-18 ワイルドカード (* ?)
LSX-Dodgers 本体の機能で、移植版でも `dir *.com` / `dir m?a40.com` が動作する(エミュレータで確認、test_all.sh に4イメージ分のテスト追加)。

### 5-19 LOCK / KANA キー
- キーマトリクス列11: D1=LOCK, D3=KANA(キーが押されている間ビットが0。ロック式かどうかは実機で未確認。エミュレータのWeb UIではラッチ動作)。`CHKEY` で KANA を `_KEYST` の bit1 に取り込み、カナ用の2表(`KANA_TABLE` / `KSHIFT_TABLE`、JIS X 0201 半角カナ、配列はJIS)を選ぶ。CTRL が優先。LOCK は表引き結果が `a`〜`z` なら大文字化(`CHKEY3`)。
- 表が5枚(112B×5)になったので `TABLEAD` を 0ED40H → 0ECA0H に移動(表の終端は `AT_WORK`=0EE90H のまま)。
- 表示は VRAM にコードをそのまま書くだけで半角カナ(A1〜DFH)が出る。ファイル名にカナを使えるかは未確認。
- 実機のキー刻印位置(資料「読み取りが不確か」)のため、特に行7〜9のカナは実機で要確認。

### 5-20 ブートローダの堅牢化
- `src/M25BOOT.ASM`: 1セクタの読み出しを最大5回試す(失敗のたびに RESTORE してシークし直す)。`FDCMD`(BUSY待ち)と DRQ 待ちにタイムアウトを追加し、超えたら Force Interrupt(D0h)を出して失敗扱い。最終的に失敗なら従来どおり `E` を表示して停止。ローダは257→344バイト(上限8KB)。
- テスト: `tools/make_bad_boot_disk.py` で LD2500.BIN の2セクタ目を CRC エラー/RNF にしたD88を作り、`E` で止まる(ハングしない)ことを確認。タイムアウトの値(DRQ待ち 65536×3回、BUSY待ち 65536×6回)は6MHz想定の概算で、**実機/実時間での妥当性は未確認**。

### 5-21 OS側ディスクドライバのエラー処理(調査結果)
- `M25DISK.ASM`(原本 `M7DISK.ASM` ベース)は、読み書きエラー時に2回まで再試行し、RNF/最終失敗時はそのドライブのシリンダを「不明(0FFH)」にして次の `SEEK` で RESTORE する(原本どおり。移植で変えていない)。READY 待ちは VBLANK 基準でタイムアウトする(§5-14)。
- 無い物: セクタ読み出し中のデータ(DRQ)待ちループのタイムアウト。MB8877が読み出しコマンドを必ず完了させる(インデックスパルス5回で RNF)前提。インデックスが出ない異常なメディアでは理論上止まりうる(未検証・未対応)。
- テスト: 全セクタが CRC エラーのデータ領域(`make_bad_boot_disk.py ... data`)からの `COPY` が `Error!` で終わり、その後 `DIR` が使えること(4イメージ、エミュレータ)。

### 5-22 MON コマンド(IOCSのROMモニタ)
- MZ-2500 のIPL ROMにはモニタがあり、IOCS機能00h(`RST 18H; DB 00H`, MONOP)で入る(`*` プロンプト。`D アドレス`=メモリ表示、`R`=呼び出し元へ復帰。他のコマンドは未調査)。**S-OS移植版(`m` コマンド)の動作を参考にして実装した**。以前の `MON`(PC3=0 で RST 0)は推測で、何も起きなかった。
- IOCSのコード/ワークは低位RAM(0000h-182Fh、ほか2360h-25FFh)にあり、LSXのページ0/TPAが上書きする(RST 18h のベクタ `0018h: JP 0185h` も消える)。→ 起動時(`M25INIT.ASM` の `INIT` 冒頭、TINIT後)に 0000h-25FFh をページ0Ch,0Dh(バンク2,3に出して4000h-65FFh)へ退避。`MON` 時に LSX のページ0(0000h-00FFh)を同ページの 6600h へ退避 → IOCS RAM を戻す → `C6h`=07h(IPL終了時の値)、IM2/I=02h、EI → `RST 18H; DB 0` → 復帰後に `C6h`=08h、ページ0を復元、画面クリア(0Ch)、`CPM_WBOOT`。
- **スタックは低位RAM(SP=1900h)に置く**。SP=FC00h(バンク7)ではモニタの `D` が `:0000=` まで出して暴走(IPLが再起動してディスクを読み始める)。原因は切り分けのみ(S-OS版と同じ1900hで直った)。
- IOCSなし80桁版は、IOCS内部が40桁前提なので `MON` の前後でCRTCを40桁/80桁に切り替える。
- 制限: `MON` はTPAの内容を壊す(IOCS RAMで上書き)。ページ0Ch,0Dh は他で使われていない前提(EMMはポートI/Oで、拡張RAMはページ10h以降なので、本移植のE:/F:とは衝突しない)。BDOS関数や外部からの呼び出しは未対応(コマンドのみ)。

### 5-23 ビープ
- 以前の `CTRL07`(コピー元の概算: 1周期5256T=約1.14kHz、90周期≒78ms)を、IOCSの `BELL`(機能20h)に合わせた。`MON` の実験で `RST 18H; DB 20H` を呼び、`--trace-io` で IOCS が `E2h`(PC2=ダイレクトサウンド、bit2)を 44h/40h で3147Tごとに切り替えるのを実測 → 周期6294T=**953Hz**(エミュレータのCPUは6MHz、フレーム108300T≒55.4Hz)、49周期≒51ms。`CTRL07` は `B=240`(DJNZ 1回=13T×240)・`C=49` で1周期6296T。
- 発音は 8255 の PC2(`E3h` のビット操作で `E2h` bit2)。YM2203(OPN)は使っていない。IOCS BELL は OPN に何も書かなかった(`--trace-opn`)。
- 注意: `E2h` には他に bit3(=0でパワーONリセット強制)、bit1(=0でRESET)がある。ビット操作(`E3h`)なら他のビットを触らないので安全。

### 5-24 ドライブ3,4 / EMM(E:) / RAMディスク(F:)
- **ドライブ割り当て**: A:,B:=FDD1,2 / C:,D:=FDD3,4(外付け) / E:=EMM / F:=RAMディスク / G:,H:=未使用。原本のM7版(C:=CMOS, E:=EMM, F:=RAM)に近い並び。
- **ドライブ3,4**: `DCH`(出力)は b7=モータ、b2=選択有効、b1-b0=00..11でドライブ1..4(`MZ2500_IO_ports.md`)。`M25DISK.ASM` の `SEEK` が `_DRIVE<2` だけ通していたのを `<4` に。LSXのシリンダ表 `_CYL0..3` は元から4台分。DPBはA:,B:と同じ(UNITNO=2,3)。**エミュレータはFDD2台なので、動作確認は「実体なしでErrorから続行」まで。**
- **EMM(MZ-1R37)**: `ACh`(出力)= アドレス19-16がBレジスタ(A15-A8)の下位4bit、アドレス15-8がデータ。`ADh`(入出力)= アドレス7-0がBレジスタ、データが読み書き。自動加算なし。ゆえに256Bごとに `OUT (ACh)` でページを選び、Bを0..255で回す(`INIR/OTIR`は使えない)。1セクタ=512B=2ページ(ページ番号 p=2*セクタ、p+1)。原本の `EMM.COM` は機種ID0専用で動かないため使わない。大きさは `MEMDISK`(INIT)が64KB単位で検出(各ブロック先頭1バイトを反転して書き戻せるか+ブロック0が変わらないか=折り返し検出。確認後は元の値に戻す。最大10=640KB)。DPB(E:)の `FATLN/MAXCL/DIRPS/ADDCL` を計算して書き込む(FAT=ceil(192N/512), ルート8セクタ)。**自動フォーマットしない**: EMMは他のOS(S-OS等)の記憶領域でもありうるので、ユーザーが `FORMAT E:` する(論理フォーマットで通る。エミュレータで確認)。
- **RAMディスク**: 拡張RAMのページ10h-1Fh(8KB×16=128KB、`mz_2500_i_o_map.md`のMB表)。512B×256セクタ(予約1+FAT1+ルート8+データ246、空き125952)。`MEMDISK` が、ページ1Fhをバンク2・ページ10hをバンク3に割り当てて反転書き込みで有無を確認(1Fhが10hの折り返しでないことも確認)。無ければ DPB(F:)の `FATLN=0`(未使用)のまま。あれば先頭8バイトのタグ `LSX25RD` と FAT先頭 `FAh` を調べ、無ければセクタ0-9を0にして書き直す(=フォーマット)。**ここでエミュレータはRESETで拡張RAMを消すため、タグがあるときに残す経路は未検証。**
- **RAMディスクの常駐ドライバ**(`M25MEM.ASM`): ページをCPUのバンク5(A000h-)またはバンク3(6000h-)へ一時的に割り当て、呼び出し元のバッファへ直接 `LDIR` する。窓にするバンクは、バッファ(512B)の末尾がバンク5より下ならバンク5、そうでなければバンク3(バッファと窓が重ならない)。割り当て中は `DI` で、スタックを使わず `LDIR` と `OUT` だけを行う(呼び出し元のスタックが窓のバンクにあっても壊れない。コードはバンク6,7にあるので影響されない)。終わったら窓を通常のページ(バンク5=0Bh、バンク3=03h)に戻す。**TPAの内側(C000hなど)には何も置かない。** 初版はC000hに中継バッファを置いていたため、C000h付近まで使う大きなプログラムをF:から読み込むと壊れた(50KBのCOMで再現して修正。`tools/make_big_com.py`)。
- **2HDについて**: 資料(IO_ports/I/Oマップ/IOCS)にあるのは2D/2DDまでで、2HDドライブがMZ-2500に存在するか、オプションがあるかは確認できていない(ユーザーも不明)。実装していない。DPBの `DPB_FDMODE` に0FEH(2HD)の値はあるが、MZ-700版からの名残で、MZ-2500では使っていない。
- **コード量**: 常駐は約200バイト増(`AT_TABLE` 前の詰め物288Bの範囲)。`body_syms` に `_DEVICE` を追加(INITからDPBを書き換えるため)。`M25DISK.ASM` は生成物なので `tools/make_m25_from_m7.py` も同じ変更にしてある(再生成で一致を確認)。
- **テスト**(`tools/test_all.sh` に22件追加、計68件): C:,D:実体なし ×4 / E:,F:の検出(--no-emmで0) ×4 / F:,E:経由のコピーのバイト一致 ×8 / 全域(F: 12ファイル、E: 15ファイル)の先頭と末尾の一致 ×2 / F:から50KBのCOMを読み込んで実行 ×4。
